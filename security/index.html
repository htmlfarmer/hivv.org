Security through living trust

A distributed hive is only as honest as its bees. HIVV secures the network with cryptography you can verify, reputation you can measure, and — uniquely — discipline borrowed from real human spiritual practice. Superintelligence needs both kinds of intelligence: logical and spiritual.

🐝 Cryptographic identities for every bee

Every bee holds an Ed25519 keypair that never leaves its own machine (private key in ~/.local/share/hivv/identity/, mode 0600). The public identity is self-certifying: the principal hivv_<sha256(pubkey)[:32]> is a function of the key — nobody can claim an identity they don't hold the key for.

  • Signed registration & heartbeats — a bee's presence is a signed statement, not a bare secret. Clock skew is advisory (recorded, never fatal); replayed statements are refused; the signed statement must cover the machine id the request presents.
  • Rotation without grief — hivv identity rotate: the current key signs its successor, so a key handover needs no legacy proof. A bee that lost its key recovers with its node secret + machine id.
  • Capability manifests — tools and models a bee advertises are signed with a monotonic sequence number: self-reported claims became attestations.
  • Revocation (CRL) — GET /api/identity/revocations. A revoked key authenticates nothing; the legitimate bee mints a fresh key and rebinds. Operators can revoke; a bee can revoke itself.
  • Operator endorsements — a separate operator key signs "this bee is mine, role owner" (GET /api/identity/endorsements) — web-of-trust, opt-in.

🧾 Signed receipts for every answer

Every chat response can carry an X-Hivv-Receipt header: the hub's Ed25519 signature over what it observed — which bee, which model, which transport, when.

  • Non-streaming answers include the answer digest — hash the body you received and match it against the signature. You don't have to trust us; you can check us.
  • Streaming answers attest attribution (the body didn't exist when the header went out).
  • Verify anything with hivv identity verify '<base64 receipt>' — exit 0 valid, exit 1 not.
  • Hub public key: GET /api/identity/hub-key · verify endpoint: POST /api/identity/verify.
  • Bees also sign their own execution receipts for repair work — bounded, deduplicated rings per node.

📊 Measured trust — unknown is never zero

Routing doesn't take a bee's word for anything. Trust is computed from evidence, per dimension:

  • identity (bound key, fresh verification, signed manifest) · reliability (quarantine = measured zero, flaps, heartbeat recency) · history (honey rank) · receipts (signed outcomes ratio)
  • A dimension with no data is null — "unknown" and "measured zero" are different truths.
  • See yours: GET /api/identity/trust/<bee> or hivv node <bee>.
