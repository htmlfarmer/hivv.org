Step 1 — Discover & Connect

Returns: {"ok":true,"uptime":...,"nodes":...}
2.
List available models
GET https://hivv.org/v1/models
Returns OpenAI-compatible model list. Use "auto" to let the router pick the best one.
3.
Send a chat message
POST https://hivv.org/v1/chat/completions
Full OpenAI Chat Completions format. Stream with "stream":true.
Request Body
{ "model": "auto", "messages": [ {"role": "user", "content": "What is HIVV?"} ], "stream": true, "route": { "mode": "fast" } }
SSE Stream Response
Each line is an SSE event: data: {"choices":[{"delta":{"content":"HIVV"}}]} data: {"choices":[{"delta":{"content":" is"}}]} Last events: finish chunk, then stats, then done: data: {"choices":[{"finish_reason":"stop","index":0,"delta":{}}]} data: {"hivv_stats": {"tokens_per_sec":64}} data: [DONE]
Full Response (non-streaming) — "stream":false
{"id": "chatcmpl-abc123", "object": "chat.completion", "model": "gemma-4-E2B-it-Q4_K_M", "choices": [{ "index": 0, "message": {"role": "assistant", "content": "HIVV is a distributed AI network..."}, "finish_reason": "stop" }], "usage": {"prompt_tokens": 12, "completion_tokens": 42, "total_tokens": 54} } Response headers include: X-Hivv-Answered-By: ashy/gemma-4 (direct) X-Hivv-Policy: ALLOW compute
Route Modes — Control How Your Request is Routed
Add "route":{"mode":"..."} to your request body. Default: balanced.
balanced
Default. Mix of speed, quality, and cost. Best general-purpose mode.
quality
Prefer the best model available (GPT-4o, Claude). May be slower.
fast
Lowest measured latency. Prefers local hardware and fast cloud endpoints.
cheap
Free compute first, cloud last. Filters by max_cost per token.
private
Localhost + hive peers only. Cloud providers removed from candidates.
trusted
Only nodes with trusted reputation scores. Highest reliability.

Fields for /api/keys/donate: provider (required) · api_key (required) · endpoint (optional — custom URL, stored on YOUR key) · name (optional) · model (optional preferred model) · personal (optional true — only YOUR requests can spend it; needs a login or a registered bee) · Keys are AES-256-GCM encrypted at rest. Without personal the key is a donation — every bee on the hive can spend it (capped at 120 req/hour + 200k tokens/day).
Capabilities & Policy Gate
HIVV has a tri-state permission system. Every action gets YES (auto-allow), MAYBE (ask human), or NO (deny).
GET/api/capabilities— what actions the hive supports (reasoning, vision, web.search, etc.)
GET/api/policy— YES/MAYBE/NO defaults for each action type
GET/api/capabilities/route/dry-run— simulate routing without executing
Risk tiers: compute (chat — free, fast-path) · data (web.fetch, database — MAYBE, then standing grant) · execute (code — sandboxed, admin-approve) · financial/physical (denied until backend exists)

What does "model":"auto" do? The router tries endpoints in this order: your own keys → local hardware (free, — tok/s measured) → peer nodes (via relay) → community key pool → cloud providers (OpenAI, Anthropic, etc.). Order is biased by measured speed (EWMA). Every response includes X-Hivv-Answered-By header showing which node/model answered.

🔌 Plug into Any AI Tool in 30 Seconds

Drop HIVV directly into Python, Node.js, Open WebUI, or Continue.dev using the standard OpenAI client.

python 
from openai import OpenAI

client = OpenAI(base_url="https://hivv.org/v1", api_key="any")

# Non-streaming
response = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Hello HIVV!"}]
)
print(response.choices[0].message.content)

# Streaming
stream = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Hello HIVV!"}],
    stream=True
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
